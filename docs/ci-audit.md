# Аудит CI — 23 октября 2026

После этого аудита экспорт SDK-образа в CI заменён на выполнение проверок
в BuildKit и экспорт бинарника. Текущий путь описан в
[ci-buildkit-tests.md](ci-buildkit-tests.md); исходные замеры ниже сохранены
для сравнения.

Проверены весь `.github/workflows/ci.yml`, Dockerfile, build context,
`tools/verify-image.sh`, Go-тесты, последние запуски Actions и состояние `main`
через GitHub API. На момент проверки локальный HEAD совпадал с удалённым
`b2b49cb1ff04eb4319d6f6ee6f8427b191063eab`. Описанные ниже локальные измерения
выполнены до публикации PR; результаты GitHub CI проверяются для конкретного
head SHA отдельно от этих измерений.

## Исходные измерения

Последний [push в main](https://github.com/mitetenov/fatsecret-tg-bot/actions/runs/39856082230)
занял 3 мин 27 с от старта до завершения. Длительности шагов по API GitHub:

| Шаг | AMD64 | ARM64 |
| --- | ---: | ---: |
| Собрать и загрузить тестовый образ, экспортировать кеш | 53 с | 60 с |
| gofmt, vet, race-тесты | 78 с | 56 с |
| Production-сборка | 28 с | 22 с |
| Проверки production-образа | 1 с | 1 с |
| Отправка образа по digest | 3 с | 4 с |
| Вся job, включая служебные шаги | 180 с | 159 с |

Публикация общего manifest заняла ещё 20 с. Сумма длительностей трёх job —
359 runner-секунд; это время выполнения, а не расчёт тарифицируемых минут.

В [предыдущем PR-запуске](https://github.com/mitetenov/fatsecret-tg-bot/actions/runs/39855151721)
только тестовый образ AMD64 занял 219 с, а весь workflow — 5 мин 56 с.
Двух запусков недостаточно для p50/p95; сравнивать их как гарантированный эффект
прогретого кеша нельзя. Они показывают, что перенос слоёв и компиляция — основные
кандидаты для оптимизации.

Локальный тестовый образ занимал 1,37 GB по `docker image ls`; внутри него
`/go/pkg/mod` занимал около 435 MiB. Это размеры распакованных данных, а не
сетевого трафика. В образе отсутствовал `/root/.cache/go-build`: результаты
`docker run --rm ... go test` терялись после каждого запуска.

## Что уже устроено правильно

- AMD64 и ARM64 проверяются параллельно на нативных Linux runner'ах. QEMU нет.
- PR не получает Docker Hub token; публикация запускается только для push в main.
  Используется `pull_request`, без выполнения PR-кода через `pull_request_target`.
- `GITHUB_TOKEN` имеет только `contents: read`.
- Тесты работают с реальной временной SQLite, локальными HTTP-сервисами и
  Python fixtures. `--network none` исключает обращения к Telegram/FatSecret.
- Обе архитектуры проходят race detector и smoke test конечного scratch-образа:
  миграция Python SQLite, исправление root-owned тома, uid/gid 10001, heartbeat
  и отрицательный healthcheck. Используются отдельные одноразовые тома.
- Финальный образ содержит статический бинарник и CA; Go, исходники и тесты
  остаются за его пределами. `.dockerignore` использует allowlist.
- Публикация manifest зависит от успеха всей матрицы, digests передаются через
  артефакты со сроком хранения один день. Сохраняется тег SHA для отката.

## Внесённые изменения

1. **Сохранён кеш компиляции Go.** `actions/cache` восстанавливает каталог на
   runner, который монтируется в тестовый контейнер как `GOCACHE`. Ключ включает
   Linux, архитектуру, Dockerfile, go.mod/go.sum и исходники. При изменении кода
   restore-prefix позволяет использовать совместимые записи: корректность
   инвалидирования обеспечивает Go. Обновление SDK/зависимостей создаёт отдельную
   область кеша. В кеш не попадают состояние бота или ключи.
2. **Production-бинарник собирается в тестовом контейнере.** `tools/ci-go.sh`
   выполняет gofmt, отдельный vet, race-тесты и статическую сборку. vet использует
   те же build flags и `CGO_ENABLED=0`, что и production-сборка. Тесты сохраняют
   `CGO_ENABLED=1` для race detector. Повторный vet внутри `go test` отключён,
   поскольку полноценный vet уже завершился выше. `-count=1` исключает повторное
   использование результата теста. Контейнер работает без внешней сети и под
   uid/gid runner, поэтому кеш доступен для последующего архивирования.
3. **Добавлен `ci-runtime`.** Docker только копирует `.ci-bin/fsbot` в общий с
   обычной source-сборкой rootfs. CI больше не запускает отдельную Docker-стадию
   компиляции. Перед публикацией проверяются SHA версии и прежние smoke tests.
   Default target `runtime` сохраняет самостоятельную сборку из исходников.
   Компромисс: Docker provenance этой стадии описывает упаковку готового бинарника;
   для attestations самой компиляции потребуется отдельно связать workflow,
   исходный commit и digest бинарника.
4. **Обновлены и закреплены Actions.** Используются проверенные SHA актуальных
   major-версий: checkout v6, cache v5, Buildx v4, build-push v7, login v4,
   upload-artifact v7, download-artifact v8. Предыдущий запуск уже сообщал о
   принудительном переходе старых Node 20 Actions на Node 24. Для обновления SHA,
   Go-модулей и базовых Docker-образов добавлен еженедельный Dependabot.
5. **Ограничены лишние ресурсы и прерывания.** Job матрицы имеет timeout 15 минут,
   manifest — 5 минут, отдельный Go-тест — 5 минут. Build records хранятся 3 дня.
   PR отменяет устаревшие запуски; main не прерывается между отправкой digests и
   manifest. В job manifest используется driver `docker`, без запуска отдельного
   BuildKit container. Checkout не оставляет Git credentials.
6. **`latest` обновляется после проверки manifest.** Сначала публикуется тег SHA,
   затем проверяется набор Linux AMD64 + ARM64, и только потом этот manifest
   получает `latest`. Ошибка проверки больше не оставляет новый `latest`.

Docker отдельно предупреждает: `cache-to: type=gha` сохраняет слои, но не
содержимое `RUN --mount=type=cache`. Поэтому прежний кеш Go в build-стадии помогал
на одном builder, но не обеспечивал инкрементальную компиляцию на новом runner.
Новый CI явно сохраняет каталог компилятора. Обычная локальная source-сборка
продолжает использовать BuildKit cache mount.

## Проверка и границы измерений

На локальном Docker Desktop, Linux ARM64, Go 1.27.3, 10 доступных CPU и 8 GiB
памяти выполнен один и тот же `tools/ci-go.sh` с `--network none`, непривилегированным
uid и bind-mounted `GOCACHE`:

| Проверка | Пустой GOCACHE | Повторный запуск |
| --- | ---: | ---: |
| vet + все race-тесты + production-бинарник | 37,7 с | 5,6 с |
| Сам пакет тестов | 2,46 с | 2,44 с |

Непрерывно выполнялись сами тесты; ускорилась компиляция. Распакованный GOCACHE
после первого прохода занимал около 350 MiB. Замер не включает создание образа,
получение/сохранение кеша GitHub, очередь runner и публикацию. Это локальное
подтверждение работоспособности кеша, а не обещание ускорить весь CI в 6,7 раза.
Первый запуск на GitHub потребует заполнения нового кеша.

Дополнительно прошли actionlint 1.7.12, `sh -n`, `git diff --check`, сборка
текущего test target и smoke test `ci-runtime` с проверкой SHA версии.
Обычный `docker build` успешно выполнен без `.ci-bin/fsbot`; его ARM64-бинарник
побайтно совпал с результатом нового CI-пути. SHA-256 обоих бинарников:
`a2c15b9de3ca6a53ad324ec8e629467b7854ae289efd3822e99724f5791234f5`.
Нативный AMD64 runner и реальный restore/save GitHub cache не входят в локальный
замер; их результат проверяется в запусках изменённого workflow на GitHub.

## Следующие улучшения по приоритету

| Приоритет | Предложение | Зачем и ограничения |
| --- | --- | --- |
| P1 | Защитить main: обязательные два matrix-check и запрет force-push | GitHub API вернул `protected: false`, rulesets — пустой список. Сейчас зелёный CI не является обязательным условием merge. Перед настройкой сверить точные названия checks; настройка репозитория в этом аудите не изменялась. |
| P1 | Добавить `govulncheck` и сканирование конечного образа | Сейчас нет ни Go vulnerability check, ни scanner образа. Начать с расписания и запуска при изменении go.mod/go.sum/Dockerfile; блокировать подтверждённые применимые уязвимости с определённой политикой исключений. База scanner должна обновляться, результаты нужно сохранять. |
| P2 | Добавить actionlint и проверку shell-скриптов в CI | В репозитории пока нет автоматической проверки workflow. Запускать при изменении `.github/**` и `tools/*.sh`, фиксируя версии инструментов. Сам изменённый workflow проверяется actionlint локально. |
| P2 | Пропускать тяжёлые job для чисто документационных изменений | Сейчас любой PR запускает обе архитектуры. Нужен анализ путей и обязательный итоговый check, который всегда завершается. Простое workflow-level `paths-ignore` может оставить required check в Pending. Не пропускать изменения Dockerfile, Go, fixtures, smoke/CI-скриптов, .dockerignore и workflow. |
| P2 | Замерить 10–20 запусков после изменения и кеш | Сравнивать p50/p95 полного CI, сумму runner-секунд, cache hit и время импорта/экспорта отдельно для PR/main и архитектур. Следить за лимитом хранения: новый ключ исходников создаёт новую копию кеша, а большая история может вытеснять полезные данные. |
| P2 | Уменьшить перенос тестового SDK, если он остаётся узким местом | Даже с быстрым Go остаётся загрузка большого тестового образа. Следующий вариант — SDK/tooling image без исходников с bind mount или native setup-go с отдельными Docker smoke tests. Сначала сравнить cold/warm время и суммарные ресурсы; сохранять изоляцию и проверки обеих архитектур. |
| P2 | Зафиксировать digest базовых Docker-образов и добавить SBOM/provenance | SHA Actions не фиксирует `golang:1.27.3-alpine`, `alpine:3.23` и frontend Dockerfile. Multi-platform digest pinning должен обновляться автоматикой. Проверить сохранение attestations после локального `load` и повторной отправки; при необходимости отдельно проверить Cosign/OIDC и права публикации. |
| P3 | Добавить `merge_group`, если включается merge queue | Сейчас событие не обрабатывается. Оно требуется при переходе на очередь merge, но включать его без самой очереди нет пользы. |
| P3 | Документировать выпуск и откат по digest | SHA-тег уже есть, но tags изменяемы. Для конкретного развёртывания фиксировать digest и после обновления проверять version/health контейнера. Автодеплоя в этом workflow нет. |

Шардинг небольшого набора тестов, сокращение ARM64-проверок, QEMU и более дорогие
runner'ы сейчас не обоснованы: сами тесты занимают около 2,5 секунды, а основная
работа — компиляция и перемещение образов. Отмена обязательных проверок ради
ускорения не требуется.
